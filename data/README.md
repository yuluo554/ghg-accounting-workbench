# data/ 数据台账

> 规则（ai-tool-project-sprint 阶段 1）：每份数据登记来源与许可；规范条目挂出处 + status（`verified`/`pending`）；程序化自制带真值数据是核心资产（固定输入可复现）。`_private/` 目录不入仓。
> 纪律：**未挂原文核对不得落库/生效/进入计算路径**；搜索摘要一律不采信，数值以官方原文/标准页面直连核对。

### M0 数据初态说明（刻意的诚实初态）

- 40 份规则包由生成器产出，**全部政策数值字段为 `null`、`status: "pending"`**——未挂官方原文核对不得生效；因此 `ghg calc` 在 M0 必然被门控拦截（退出码 1），这是设计行为。
- 生成器为**唯一写入者**：产物禁手改；改体例走 `rulesets` 生成器整目录重生成，配"再生成逐字节一致"守门测试（`code/tests/test_frozen_data.py`）。
- 坐标空间 = 2 版通则 × 5 年度（2022–2026）× 4 行业 = **40 格**；索引单点 = `data/rules/manifest.json`（含各产物 sha256）。
- `units.json` 单独标注 `verified`：单位换算因子属**定义性关系**，不是需要发文核对的政策数值（决策见 plan/06 D0-8）。

## 三、合成数据纪律

- **假企业白名单**：合成企业统一使用虚构名称（如"示例钢铁（合成）有限公司"）+ 虚构统一社会信用代码须符合校验位算法但**不得与真实企业冲突**（采用保留测试号段约定，入库时登记）；不得使用任何真实企业名称、产能或排放数据。
- **植入真值**：合成企业档案由 `tools/gen_synthetic.py` 生成时同时产出**期望核算结果**（活动数据×因子，逐源分解），真值随档案入库，引擎以独立实现路径对账（双路对账）。
- **因子来源标注**：合成档案使用的因子必须标注为官方因子库/缺省值，并记录因子版本；虚构因子仅可用于单元测试，须显式标记 `synthetic=true`，不得进入基准真值。
- **可复现**：生成器固定随机种子，同一输入必得同一输出；产出物 sha256 留档。

## 四、法律与许可口径

- 规则包 JSON 中的标准/条款信息以"标准号 + 条款号 + 要点"形式呈现（规避全文转载），原文以官方页面为准；
- data/knowledge/raw/ 快照为官方公文与标准页面（著作权法第五条官方文件不适用版权保护）；
- 合成数据与真值库为本项目自制（固定输入可复现），MIT 许可随仓库发布。
