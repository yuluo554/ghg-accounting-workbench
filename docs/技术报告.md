# 技术报告：企业温室气体排放核算与报告工作台

> 面向对象：技术评审 / 竞赛评委 / 接手维护者。
> 状态：M5 完成（2026-10-13）。本报告随代码同仓维护，**不是**一份写完即过期的说明书。

---

## 一、要解决的问题与设计取舍

企业温室气体核算的算术本身不难（活动数据 × 排放因子），难的是三件事：**这个源该不该算**、
**这个数字从哪来**、**换个标准版本还对不对**。这三件事决定了本项目的四个设计取舍：

| 取舍 | 选择 | 理由 |
|---|---|---|
| 规则放哪 | **规则包 JSON + status 门控**，不写进代码 | 数值可以逐条挂官方原文核对；代码里出现政策数值一律门禁拦截 |
| 什么时候能算 | **未核对（`pending`）绝不进入其自身计算路径** | "不知道就报错"比"猜一个数算出来"安全得多 |
| 计算怎么留痕 | **逐源三元组**（活动数据来源 / 因子来源 / 规则条款）+ 溯源表 | 核查要的是"每个数字追到来源"，不是"结果对不对" |
| 标准版本怎么处理 | **三维坐标强约束**，跨坐标混算直接报错 | 新旧标准切换期最危险的错误是"用错版本的规则却不报错" |

### 1.1 双标尺（GB/T 32150-2015 vs -2025）

2025 版于 2026-07-01 实施并全部代替 2015 版，企业正处切换期。本工具把两版都做成坐标维度
（`standard`），并给出**排放源级差异**：新增 / 取消 / 口径调整 / 未变化。

差异判定不是"比对两版文本"，而是：

1. 以新版规则包内 **`delta_vs_2015` 声明**为准（该声明逐条挂官方条款核对）；
2. 用两版同 id 条目的**结构字段变化**交叉校验；
3. 声明与结构不一致 → 直接抛 `BoundaryError`（退出码 2）。

第 3 条是关键：它让"声明"与"事实"必须自洽，而不是单方面相信声明。

### 1.2 三维版本化规则集

```
Coordinate = (standard, year, industry) = 2 × 5 × 4 = 40 格
```

一维化为 `data/rules/ruleset-<standard>-<year>-<industry>.json`，由 `manifest.json` 单点索引。
**代码内零坐标字面量**：标准短键、年度清单、行业名全部来自 manifest（与零政策数值同一条纪律）。

坐标空间是"规则包可寻址空间"，**不等于"每格都已核对"**——这是刻意的诚实初态。

## 二、status 门控：本项目最核心的机制

### 2.1 三种状态

| status | 含义 | 行为 |
|---|---|---|
| `verified` | 已挂官方原文核对 | 可进入计算路径 |
| `pending` | 待核对（含 `value: null`） | **其自身路径上必然拦截** |
| `input_required` | 该数值**本不由规则包承载**（如平台测算公布的行业平衡值） | 放行门控，由试算层运行时显式索取 |

`input_required` 是第三态，容易与 `pending` 混淆：前者是"这不是我们该印的数"，
后者是"我们还没核对这个数"。混为一谈会导致两种错误——把平台数据当政策数值硬塞进规则包，
或者把"不该由规则包承载"当成"没核对"而永久拦截整条路径。

### 2.2 按计算路径分作用域

门控单点 `RulesIndex.effective_ruleset(coord, scope)` 分三条作用域：

| scope | 校验的块 | 未生效时的退出码 |
|---|---|---|
| `calc` | standard / boundary / engine / factors | 1 |
| `quota` | quota | 1 |
| `check` | quality | 1 |

**为什么分作用域**：把"整包全 verified"当唯一门，会让与核算无关的 pending
（三行业配额平衡值仅平台可查、校核阈值属工程定值）阻断整个核算路径。
分作用域后，`pending` 只在其自身路径上拦截，不牵连其他路径。

实测结果：核算路径 38/40 可通过，校核与配额路径 40/40 可通过。
被拦的 2 格是"新旧通则 × 2026 发电"——该年度碳氧化率改由官方因子库取值，而因子库站点
WAF 阻断（HTTP 412），未能摘录。**这是诚实留白，不是缺陷**：按纪律不编造数值，
台账如实留空并登记访问状态。

### 2.3 门控的三重设防

1. `effective_ruleset()` 是唯一进入计算路径的入口（测试锁定"绕过即缺陷"）；
2. 基准层把"门控能正确拦截未核对条目"纳入检查（不掩盖留白）；
3. `pending` 的校核规则**不执行**并记入 `rules_skipped`（不得以未核对阈值报结论，
   也不得静默按"通过"处理）。

## 三、因子来源优先级与单位换算链

### 3.1 优先级（FR-02.4）

```
实测（档案自带） > 官方因子库 > 行业缺省
```

三层皆不可用 → `FactorUnavailable`（退出码 2，**绝不静默取 0 或 1**）。

两条防绕过的设计：

* 档案自报因子来源必须落在规则包 `factors.priority` 白名单内，否则视为输入不可用；
* 自报"行业缺省"时，仍须与规则包缺省值**对账**——防止用任意数值冒名缺省因子。

### 3.2 单位换算三段式

```
活动数据 → 量纲基本单位        （kg → t）
因子     → 每基本单位          （tCO2e_per_kg → tCO2e_per_t）
排放量   → tCO2e
```

每一步都记进 `UnitChain.trace()`，进报告 §4「核算过程」。复合单位的分隔符定义在
`units.PER_SEPARATOR`（单一真相源），避免校核层与计算层各写一份拆分逻辑。

## 四、数据质量校核（FR-04）

四类检查按规则包 `quality.rules[].type` 分派：

| 类型 | 判据 | 阈值来源 |
|---|---|---|
| `unit_consistency` | 活动数据单位 ↔ 因子分母量纲一致且可识别 | — |
| `magnitude_outlier` | 单源排放量占全厂合计的占比上限 | `quality.thresholds.magnitude` |
| `yoy_jump` | 同一源活动数据跨年度变化率上限 | `quality.thresholds.yoy` |
| `intensity_plausibility` | 全厂比强度落在声明区间 | `intensity_min` / `intensity_max` |

三条设计纪律：

1. **零阈值字面量**：阈值全部从规则包读出，代码内不出现任何阈值数值（NFR-07）；
2. **只读层**：校核不改 `CalcResult` 任何字段（前后逐字节比对锁定）；
3. **分级可降级**：规则的 `level` 是"硬违规"级别；当违规**可被显式换算/可解释**时降一级报出
   （如"单位口径不一致但引擎已正确换算"报 `warning` 而非 `error`），避免把引擎已正确处理的情形
   误报为致命错误。

阈值是**本工具的工程筛查判据**，非官方发布数值——规则包内 `clause.code = null` 并注明，
避免与政策数值混淆。

## 五、配额试算（FR-05）

**方法学切换即切换公式分支**，分支由规则包 `quota.method` 决定，代码不内联方法学名与公式：

| 方法学 | 公式 | 适用 |
|---|---|---|
| `benchmark` | `A = Qe × Be × Ff` | 发电（碳排放强度基准法） |
| `intensity_coefficient` | `A = E × (1 + α)` | 钢铁 / 水泥 / 铝冶炼 |
| `historical_intensity` | `A = 产量 × 历史强度` | 扩展方法学 |
| `none` | 不试算 | 显式返回"不适用"，而非静默给 0 |

其中 α 由碳排放强度偏离度 `X = (BP − Ii) / BP` 经规则包 `quota.derivation` 的分段常数推出
（斜率 / 带宽 / 封顶三段，对应方案表 3）。

**参数三态**与门控配合：`verified` 直接用规则包值；`input_required` 必须由调用方显式提供，
缺失即抛 `QuotaUnavailable`（退出码 2）；`pending` 由门控在进入试算前拦截。

**免责声明强制**（R3 / NFR-10）：`QuotaResult.disclaimer_required` 恒为 `true`，
渲染层必须输出固定声明文本——结构体里**不含可选声明字段**，让"忘记输出"在类型层面就不可能。

## 六、内置离线基准（FR-07）

三类基准一条命令跑全（`ghg bench`），退出码 0 达标 / 1 未达标 / 2 用法错误。

| 套件 | 内容 | 实测 |
|---|---|---|
| `rules` | 40 包 × 12 项结构自洽扫描（表达式文法 / 引用可解析 / 状态 / 作用域划分 / 双标尺声明交叉一致） | 480/480 |
| `factor` | 单位往返 / 基准因子恒 1 / 跨量纲拒绝 / 复合单位拆分 / 跨年不漂移 / 跨通则一致 / 优先级白名单 / 孤儿类别 | 116/116 |
| `cases` | 12 个异常用例命中 + 分级正确；8 档案真值双路对账；误报对照 | 29/29；命中 12/12；误报 0/8 |

四条让"基准通过"不等于"基准什么都没查"的设计：

1. **门槛是数据不是代码**：验收门槛取自 `manifest.bench.targets`，缺失即 `BenchConfigError`
   （退出码 2），**不回落到代码内默认值**——否则又是"抄进代码的第二份真相"；
2. **基准可证伪**：每个套件配"注入缺陷 → 必须报未达标"的探活用例；
3. **只读 + 确定性**：跑完 `data/` 逐份 sha256 不变；两次运行结果一致；
4. **不掩盖留白**：把"门控能正确拦截未核对条目"也纳入检查。

## 七、报告导出与可核证性（FR-06）

三个产物：Markdown（人读）+ CSV / XLSX（机读）。章节骨架 §0 报告头 … §8 数据溯源表。

**可核证性由断言保证，不靠自觉**：

* 溯源表行数 **必须等于** 明细表行数 + 因子来源表行数；
* 每行 `rule_entry_id` **必须**能在该坐标包内解析到具体条目（悬空即报错）；
* 不满足 → 导出失败（退出码 2），**不得导出"半溯源"报告**。

**无外链**（FR-06.4）：机读产物不写 URL，官方出处以"文号 + 名称 + 版本"文本承载
（足以定位文件），断网可开、可归档。

**字节确定性**（NFR-04）：一律 `write_bytes` + LF；XLSX 用自研最小 writer
（`ZIP_STORED` + 固定 `create_system` / `date_time`），同一输入两次导出逐字节一致。
**为什么否决 openpyxl**：XLSX 只需导出、不必引重依赖，而第三方库的 ZIP 元数据
（宿主系统、时间戳）会让字节漂移，破坏"同输入同字节"这条纪律。

## 八、双形态交付与打包

### 8.1 CLI / GUI 同源

GUI **只消费引擎 API，零判定逻辑**（FR-08.2）：唯一的引擎调用点在
`code/gui/ghg_gui/service.py`，其余界面模块经它转发。这条纪律由**静态导入门禁**锁定——
页面/视图模型若直接 `import ghg.calc` / `ghg.quality` / `ghg.quota` / `ghg.bench`，
测试直接失败。理由：界面里长出第二套引擎调用，就意味着"界面算一套、命令行算一套"的漂移面。

界面逻辑放在**零 Qt 依赖**的视图模型（`models.py`）里，Qt 页面只负责把文本塞进控件。
好处是"界面摆得对不对"这件事不需要真的画窗口就能测——offscreen 测试直接调视图模型即可。

### 8.2 打包白名单

`tools/ghg_packaging.py` 是数据白名单的**单一真相源**：随 exe 分发的 `data/**` 是显式枚举清单，
不是"整个 `data/` 拷进去"。

* 可审计：发布产物的数据面一眼可数；
* 防误带：`data/knowledge/raw/`（官方原文快照，约 11 MB）是核对留档而非运行时依赖，
  不进包；
* 有守门：`data/` 下出现未登记目录 → 打包自检直接失败。

**踩过的坑（值得记下）**：PyInstaller 的 `datas` 对目录源是把**内容**拷进目标目录，
若按"文件源"的方式算目标路径，整棵树会被拍平到 `data/`，
`data/rules/manifest.json` 这个定位标记随之消失，冻结态 exe 立刻找不到数据。
现在按源类型分别计算目标路径，并由测试锁定"定位标记可达"这条不变量。

### 8.3 冻结态自检

`exe --selftest` 是打包产物验收入口，除常规自检（坐标空间 / 门控 / 单位往返 / 报告导出）外，
**额外断言数据目录落在 exe 目录内**（冻结态专属）。实测在把 exe 拷到与仓库无关的目录后，
自检仍退出码 0。

## 九、确定性与可复现（NFR-04）

| 层面 | 做法 |
|---|---|
| 数值 | 全链路 `Decimal`，`as_decimal()` 显式拒绝 float；精度位用 `Decimal(1).scaleb(-n)` 表达（不写小数常量，避免与政策数值 token 混淆） |
| JSON | 自研确定性 writer：键排序固定、缩进 2 空格、结尾单换行、`write_bytes` |
| 生成器 | 禁 stdlib `random`、禁系统时钟、禁 set 迭代序；产物不含时间戳 |
| 守门 | 临时目录重生成 → 逐份 sha256 比对；`data/rules/**` 出现 CR 字节即失败 |
| 报告 | 时间戳只出现在报告正文（唯一允许处），不入冻结产物 |
| 基准 | 只读 `data/`，零网络、零时钟；运行时长计入指标 |

## 十、零政策字面量门禁（NFR-07）

规则包的政策数值**只能**来自 `data/rules/` 下的 JSON。引擎/CLI/GUI 源码（**含注释与 docstring**）
里出现这些 token 即视为"抄进代码的第二份真相"，一律失败。

四个关键设计：

1. **token 从数据采集**：从规则包数值字段程序化采集（现 13 个），词边界匹配
   （避免 `1000` 命中 `10000` 子串）；
2. **扫描范围只含引擎与前端**：生成器（`tools/gen_*.py`）是数据文件的**生产者**，
   必然持有模板数值，属真相源而非复制品——把生产者与复制品混扫会让门禁自相矛盾；
3. **豁免口径写死**：单位换算因子（定义性关系）、免责声明法律文本、精度位表达式、
   标准编号（元数据）——豁免必须写死，否则门禁刷屏后被运维性忽略；
4. **阳性对照**：门禁必须能对"注入的数值"命中。数据初态 token 集为空时，
   不配探活则"通过"可能只是"什么都没扫"。

## 十一、诚实的留白清单

技术报告的价值有一半在于说清楚**哪里没做完**：

| 留白 | 原因 | 影响 |
|---|---|---|
| 官方因子库（第二版）无摘录条目 | 站点（data.ncsc.org.cn）直连恒返回 HTTP 412（WAF），未能逐条摘录 | 缺省因子改由四行业指南附录 A 官方缺省值承担；台账如实留空并登记访问状态 |
| 2 格坐标核算路径被拦 | 2026 发电碳氧化率已改由因子库取值，而因子库不可达 | 核算路径 38/40；**按纪律不编造数值** |
| 三行业配额"平衡值"、发电"调峰修正系数" | 前者当年度由全国碳市场管理平台测算公布、方案正文未印；后者随机组负荷率而异 | 标 `input_required`，由试算层运行时显式索取 |
| 校核阈值 | 本工具的**工程筛查判据**，非官方发布数值 | 规则包内 `clause.code = null` 并注明 |
| 配额试算覆盖年度 | 仅方案覆盖年度（发电 2025/2026、三行业 2026） | 其余年度发电基准值标 `input_required` |

另有两处**刻意为之**、容易被误读为缺陷的地方：

* 基准的"规则自洽率 100%"指 40 包的**结构自洽**，与"核算路径 38/40 可通过"不矛盾：
  后者是**数据未核对**，前者是**规则包自身无矛盾**；
* "单位表基准换算因子恒 1"由 `UnitTable.__init__` 在加载时强制（更强的保证），
  基准层同类检查在正常数据上恒真——保留它作为"表内自洽"的显式记录，而非唯一防线。

## 十三、为什么这样组织代码

```
code/src/ghg/     核心层（零第三方依赖、零网络、零 LLM）
   ├─ 数据与坐标：coordinates / rules / paths / jsonio / decimals
   ├─ 计算：engine（表达式树）/ units / calc / boundary / pipeline
   ├─ 判据：quality（校核）/ quota（配额）/ bench（基准）
   └─ 输出：report（导出）/ cli（命令行）
code/gui/         桌面形态（只消费引擎 API）
tools/            生成器（数据真相源）/ 守门脚本 / 打包规格
data/             冻结产物（禁手改，改走生成器整目录重生成）
```

**核心层零依赖**是刻意的：计算与基准只用到标准库，意味着任何环境都能跑、
不会被依赖版本绑架；而"零网络、零 LLM"意味着结论完全由确定性规则产生——
核算工具的正确性不该建立在模型输出上。
