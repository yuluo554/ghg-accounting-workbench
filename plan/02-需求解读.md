## 一、痛点 → 能力转译表

| # | 企业侧真实痛点 | 转译为工具能力 | 落地模块 | 验收方式（可程序化） |
|---|---|---|---|---|
| 1 | 新旧标准切换期，法务/合规不敢断定"这版标准下要不要算这个源" | **双标尺排放源识别**：同一设施清单分别按 2015/2025 两版通则输出应核算源清单，并标出新旧差异（新增/口径调整/取消） | 边界识别引擎（04 §2.1） | 合成档案固定输入 → 两版输出清单 diff 与真值一致 |
| 2 | 活动数据 × 排放因子的乘法人人会算，"错在哪一项"说不清 | **逐项留痕计算**：每个排放源一行，每行挂"活动数据来源 / 因子来源 / 规则条款"三元组 | 计算引擎 + 溯源表（04 §2.2 / §6） | 报告内每行均可回指到 data 文件与条款 id |
| 3 | 跨年度/跨行业规则包随手混用，算出来还不报错 | **三维坐标强约束**：核算声明一次坐标（通则版本×年度×行业），跨坐标混算直接报错 | 规则索引 + 坐标门控（04 §1） | 混算输入 → 退出码 2，无结果输出 |
| 4 | 用了不适用的缺省因子，核查时被挑出 | **因子来源优先级 + 适用性检查**：企业实测 > 官方因子库（第二版）> 行业缺省，且校验因子与源类型/行业/年度匹配 | 因子选择器 + 校核层（04 §4） | 故意错配因子 → 校核命中且分级为"错误" |
| 5 | 申报前不知道自家数据"像不像话" | **数据质量校核层**：单位一致性、量级异常、跨年突变、比强度合理性，分错误/警告/提示三级 | 校核层（04 §4） | 合成异常档案 → 命中率与误报率进基准 |
| 6 | 配额算完和实际排放的缺口心里没底 | **配额试算**：按行业方法学（基准线法/历史强度法）试算并给出履约缺口预判 | 配额模块（04 §5） | 方法学切换 → 公式分支切换，算例对账 |
| 7 | 核查机构要"每一个数字都能追到来源"，手工做一份溯源表要一天 | **一键可核证报告**：Markdown + XLSX/CSV，含边界、逐源明细、因子来源表、依据清单、数据溯源表 | 报告导出（04 §6） | 报告头含坐标+版本+生成时间；溯源表条数与明细表行数对账 |
| 8 | 不敢把生产数据传上云做合规测算 | **全本地 / 零上传 / 零 LLM 依赖**：全部结论由确定性规则产生 | 架构选型（03） | 源码扫描：核心层无网络调用、无第三方依赖 |
| 9 | 工具算的和主管部门口径对不上，无法自查 | **内置离线基准**：规则自洽、因子一致性、边界与异常用例三类扫描，指标写进 README | 基准（05 M4） | 一条命令跑全，退出码 0 达标 |

**核心设计判断**：本项目的护城河不是"会做乘法"，而是**"每一个数字都能追到来源、且绝不会跨版本混算"**——因此"规则包 versioned + status 门控 + 零政策字面量门禁"三条纪律优先级高于功能数量。

## 二、功能需求清单（FR，带优先级）

> 优先级：**P0** = 首期必须（进评分表的"应用完整性"）；**P1** = 首期应有（评分表"技术创新性"）；**P2** = 留扩展。

### FR-01 核算边界与排放源识别（P0）
- FR-01.1 输入企业设施/工艺清单（JSON），输出应核算排放源清单，每条挂纳入依据条款 id。
- FR-01.2 支持 GB/T 32150-2015 与 GB/T 32150-2025 **双标尺**分别输出。
- FR-01.3 **双标尺差异提示**：输出两版清单的差异集（新增 / 取消 / 口径调整）。
- FR-01.4 设施清单为空或缺关键字段时，返回可用性错误（退出码 2），不得静默按空清单核算。

### FR-02 排放量确定性计算（P0）
- FR-02.1 按规则包公式树计算：`排放量 = 活动数据 × 排放因子 × 氧化率系数`（系数按源类型缺省为恒等）。
- FR-02.2 全程 `Decimal`，禁止 float 进入计算路径；呈现统一量化到约定小数位（`ROUND_HALF_UP`）。
- FR-02.3 单位换算显式化（t / kg / GJ / MJ / MWh / Nm³），换算因子一律取自 `data/rules/units.json`。
- FR-02.4 每个结果行携带 `factor_source`（实测 / 官方因子库 / 行业缺省）与 `clause` 引用。

### FR-03 三维版本化规则集（P0）
- FR-03.1 规则包坐标为 `(通则版本, 年度, 行业)`；首期空间 = 2 版 × 5 年度（2022–2026）× 4 行业 = **40 个坐标包**。
- FR-03.2 坐标索引由 `data/rules/manifest.json` 单一驱动，代码不得内联任何坐标字面量。
- FR-03.3 **跨坐标混算拦截**：一次核算只允许一个坐标；输入出现两个及以上坐标即报错。
- FR-03.4 每条数值/系数挂 `status`（`verified` / `pending`）；**`pending` 不得进入计算路径**（单点门控 `effective_ruleset()`）。
- FR-03.5 报告头固定输出"采用的规则包坐标"。

### FR-04 数据质量校核（P0）
- FR-04.1 规则化的校核规则集（JSON：id / 名称 / 依据 / 级别 / 建议），按 `type` 分派。
- FR-04.2 四类检查：单位一致性、量级异常、跨年度突变、比强度合理性。
- FR-04.3 输出分级问题清单（错误 / 警告 / 提示），每条挂规则依据 id。
- FR-04.4 校核不得修改任何计算结果（只读层）。

### FR-05 配额试算（P1）
- FR-05.1 按行业规则包配置的方法学试算（基准线法 / 历史强度法）。
- FR-05.2 预算年度配额与核算排放量对比，给出履约缺口预判。
- FR-05.3 强制输出免责声明：试算结果仅供内部预判，正式配额以主管部门核定为准。

### FR-06 可核证报告导出（P0）
- FR-06.1 导出 Markdown（人读）+ XLSX/CSV（机读）。
- FR-06.2 含：核算边界说明、逐排放源明细表、因子来源表、核算过程、依据清单、数据溯源表。
- FR-06.3 报告头固定输出：规则包坐标 + 生成时间 + 工具版本（可复现三要素）。
- FR-06.4 导出的机器可读产物不得含外链（断网可开、可归档）。

### FR-07 内置离线基准（P0）
- FR-07.1 规则自洽基准：新旧通则 × 四行业 × 多年度规则包的公式与系数枚举自洽扫描。
- FR-07.2 因子库一致性基准：同源因子跨年变化、单位换算往返。
- FR-07.3 边界与异常用例基准：边界识别、跨版本混算拦截、数据质量校核命中率。
- FR-07.4 全部零 API 依赖、固定输入可复现、单次全量 < 1 秒量级。

### FR-08 CLI 与桌面双形态（P0=CLI，P1=GUI）
- FR-08.1 CLI：`coords` / `rules` / `calc` / `check` / `convert` / `selftest` 子命令，退出码语义锁定。
- FR-08.2 GUI（M5）：PySide6 多页签，**只消费引擎 API**，不另起第二套行为。
- FR-08.3 PyInstaller onedir 双 exe（GUI + CLI 控制台）。

### FR-09 扩展位（P2）
- 其余行业（化工、造纸等）规则包；CBAM 出口侧测算；多设施汇总；审计日志。

## 三、非功能需求（NFR）

| 编号 | 需求 | 判据 |
|---|---|---|
| NFR-01 | **零网络**：核心计算与基准全程离线；程序运行不发起任何外部请求 | 源码静态扫描：核心层无 `requests`/`urllib`/`socket` 调用 |
| NFR-02 | **零上传**：无遥测、无崩溃上报、无云依赖 | 同上 + 无外部域名常量 |
| NFR-03 | **零 LLM**：全部结论由确定性规则产生，无解析兜底需求（决策记录显式留档） | 依赖清单无任何 LLM SDK |
| NFR-04 | **确定性**：同一输入 + 同一规则包 → 逐字节相同输出（含生成器再生成） | 守门测试：临时目录重生成后 `sha256` 逐份一致 |
| NFR-05 | **Decimal 精度**：金额/排放量/系数全链路 Decimal，无 float 污染 | 单元测试断言类型与量化行为 |
| NFR-06 | **可溯源**：任何对外数值均可回指规则包条目 id 与条款引用 | 报告溯源表与明细表行数对账 |
| NFR-07 | **零政策字面量**：引擎/CLI 源码（含注释与 docstring）不得出现规则包数值 token | `tools/check_zero_literals.py` 扫描通过 |
| NFR-08 | **Python 兼容**：3.8 至 3.12（3.8 为下限，CI 矩阵覆盖） | CI 三矩阵全绿 |
| NFR-09 | **核心零第三方依赖**：`ghg` 核心层只用标准库 | `pip show` 反查 + 干净 venv 验证 |
| NFR-10 | **免责声明强制**：配额试算与核算结论均带"以主管部门核定/核查结论为准" | 报告模板与 CLI 输出均含声明行 |
| NFR-11 | **性能**：单企业单年度核算 < 1 秒；40 坐标包全量扫描 < 2 秒 | 基准运行时长断言 |
| NFR-12 | **数据红线**：不使用真实企业数据；官方因子库摘录注明版本与 URL | `data/README.md` 台账 + 脱敏审计 |

## 四、边界与非目标（守卫清单）

**不做（硬边界）**
1. 不做产品碳足迹（PCF）核算（属 GB/T 24067 范畴）——不引入 PCF 术语与公式。
2. 不做碳交易撮合、报价、持仓管理。
3. 不做 CCER 项目开发与减排量核算。
4. 不做企业实测因子的实验室检测流程。
5. 不对接生态环境部申报系统、不做申报报文生成。
6. 不做多租户/云服务/账号体系。
7. 不抓取、不内置任何真实企业数据。

**软边界（可论证后扩展，需决策记录）**
- 首期行业固定四类：发电 / 钢铁 / 水泥 / 铝冶炼；其余行业以"规则包坐标扩展"方式接入，不改引擎。
- 首期通则固定两版；未来新版发布以新增坐标接入。

**合规红线（违反即视为缺陷）**
- R1 全本地核算与存储，零上传；
- R2 规则包条目 `status=pending` **不得进入计算路径**，也不得出现在任何结论性输出中；
- R3 核算结果与配额试算结果必须携带免责声明；
- R4 官方因子逐条登记来源 URL 与版本；来源不明者不得作为默认因子；
- R5 合成数据不得与真实企业重名或号码冲突；
- R6 不复制姊妹项目代码，文档不提及姊妹项目业务领域（品牌隔离）。

## 五、用户画像与典型场景

| 角色 | 场景 | 期望产物 |
|---|---|---|
| 控排企业碳管理岗 | 年度盘查前自检数据质量 | 校核问题清单 + 核算报告（内部用） |
| 第三方核查机构 | 核对受核企业申报数据的一致性 | 数据溯源表（逐数字回指来源） |
| 出口企业合规岗 | CBAM 过渡期估算（扩展位） | 排放强度汇总（P2） |
| 咨询顾问 | 多企业批量核算、跨标准对比 | CLI 批处理 + 双标尺差异表 |
| 教学/研究 | 理解新旧通则口径差异 | 规则包 JSON 与差异表（可读性强） |

**典型使用序列（CLI）**

```
ghg coords                                    # 看坐标空间
ghg rules show --standard 2025 --year 2024 --industry steel
ghg rules check --standard 2025 --year 2024 --industry steel   # 门控体检
ghg calc --input 企业档案.json --out 报告.md
ghg check --emissions 核算结果.json                             # 数据质量校核
ghg convert --value 1 --from t --to kg
ghg selftest
```
