## 二、技术选型与理由

| 项 | 选型 | 理由 / 备选否决理由 |
|---|---|---|
| 语言 | Python 3.12+（下限 3.12，v0.1.1 起） | Python 3.8 已于 2024-10-07 EOL；3.12 安全支持至 2028-10-31，且实测 3.12.10 + PySide6 6.12 + PyInstaller 6.22 全链可用（见 `plan/06` D7-1） |
| 数值 | `decimal.Decimal` 全链路 | 排放量需逐项可核证，float 尾差不可接受；JSON 加载 `parse_float=Decimal` |
| 规则承载 | JSON（schema v1） | 人可读可 diff、可冻结、可生成器产出；否决 YAML（隐式类型转换会吞掉 `2015` 这类键） |
| CLI | `argparse`（stdlib） | 零依赖；退出码语义可锁进测试 |
| GUI | PySide6（M5，optional extra） | 多页签表格密集型界面成熟；否决 Tk（表格/中文渲染弱） |
| 打包 | PyInstaller **onedir** 双 exe（M5） | onedir 启动快、便于数据定位断言；onefile 解压慢且数据定位失真面大 |
| 报告 | 手写 Markdown + CSV + 最小 XLSX writer（M5） | 零依赖可写；否决 openpyxl（XLSX 仅需导出、不必引重依赖） |
| 测试 | pytest（dev extra） | 断言友好；`pytest>=7,<9` + PyYAML（workflow 门禁） |
| CI | GitHub Actions 两矩阵 + package job | test：`windows×{3.12}` + `ubuntu×{3.12}`；package：`windows×3.12` 真构建两个 spec 并跑双 exe `--selftest`（v0.1.1 起，见 `plan/06` D7-1/D7-2） |
| LLM | **不使用** | 领域为纯确定性规则 + 结构化输入，无非结构化解析兜底需求；决策记录显式留档（02 NFR-03） |

**依赖分层（pyproject extras）**

| extra | 内容 | 用途 |
|---|---|---|
| （无） | 仅标准库 | 核心计算与基准，零依赖可跑 |
| `dev` | pytest、PyYAML | 测试 + workflow 守门断言 |
| `gui` | PySide6 `>=6.12,<7` | M5 桌面形态；下限与 Python 下限对齐（6.7+ 要求 Python≥3.9，故 3.12 上解析到 6.12.x） |
| `build` | PyInstaller `>=6.22,<7` | M5 打包；6.x 不再 `import pkg_resources`，故不再需要 `setuptools<81` 全局降级（v0.1.1 起，见 `plan/06` D7-3） |

## 四、坐标模型（三维一维化）

```
Coordinate = (standard, year, industry)
   standard ∈ { 2015版, 2025版 }          # GB/T 32150-2015 / -2025
   year     ∈ { 2022..2026 }              # 报告年度（核算年度）
   industry ∈ { power, steel, cement, aluminum }
```

- **一维化**：每个坐标一个文件 `data/rules/ruleset-<key>-<year>-<industry>.json`，`key` 为通则短键（`gbt32150-2015` / `gbt32150-2025`）。
- **索引单点**：`data/rules/manifest.json` 枚举全部坐标 + 每份包路径与 `sha256`。代码**不得**内联标准号、年度、行业名（NFR-07）。短键解析、年度合法性、行业合法性一律来自 manifest。
- **为什么不做笛卡尔积之外的"有效期"特判**：2015 版已废止、2025 版自实施日起生效——有效期是**包的元数据**（`standard.validity`），不是坐标维度；坐标空间保持规整（40 格），有效性由包内字段表达、由门控判定。

**门控单点（架构级约束）**

```python
rules_index = RulesIndex.load(data_dir)          # 唯一入口
coord       = rules_index.resolve(standard, year, industry)   # 字面量 → 坐标
pack        = rules_index.pack(coord)            # 原始包（含 pending，可预览）
effective   = rules_index.effective_ruleset(coord, scope="calc")  # 仅 verified；该作用域有 pending 必抛错
```

- `pack()` = 只读预览（CLI `rules show` 用，`--preview` 允许显示 pending）；
- `effective_ruleset(coord, scope)` = **唯一进入计算路径的入口**，按**计算路径作用域**校验该路径引用的块
  （`calc` = standard/boundary/engine/factors；`quota` = quota；`check` = quality），
  内部断言作用域内全部引用条目 `status == verified` 且 `value is not None`，否则抛 `RulesetNotEffective`
  （携带待核对条目 id 列表）。
  - **为什么分作用域**（M1 决策 D1-1）：把"整包全 verified"当唯一门，会让**与核算无关**的 pending
    （三行业配额平衡值仅平台可查、校核阈值属 M3 工程定值）阻断整个核算路径。分作用域后，
    `pending` 只在其**自身路径**上拦截（如 quality 全 pending → `check` 退出码 1），不牵连核算。
- 任何绕过 `effective_ruleset()` 直接读原始包做计算的行为视为缺陷；由测试锁定（`test_rules_gate.py`）。

## 五、精度与确定性约定

| 约定 | 口径 |
|---|---|
| JSON 加载 | `json.load(..., parse_float=Decimal)`；整数保持 `int` 后统一 `Decimal` |
| 计算 | 全程 `Decimal`，禁用 `float()` 转换（`_decimals.py` 提供 `as_decimal()` 校验） |
| 量化 | 输出层统一量化到约定小数位，`ROUND_HALF_UP`；小数位以 `PLACES` 常数 + `Decimal(1).scaleb(-PLACES)` 表达（**不写小数常量**，见下） |
| 生成器写盘 | 一律 `write_bytes`（或 `open(..., newline="\n")`），**禁 stdlib `random`、禁系统时钟、禁 set 迭代序**；键排序固定 |
| 冻结守卫 | 临时目录重生成 → 逐份 `sha256` 比对；`data/rules/**` 出现 CR 字节即失败（EOL 门） |

**为什么"不写小数常量"**：NFR-07 的零政策字面量门禁把规则包数值 token 设为禁用词，`0.01` 这类精度常量一旦与策略数值形同会互相污染判定口径。用 `Decimal(1).scaleb(-2)` 表达精度位，既避开门禁歧义，也让"精度位"成为一个显式可审计的常量。

## 六、CLI 契约（退出码锁定）

| 退出码 | 语义 |
|---|---|
| 0 | 成功 / 门控通过 / 基准达标 / 校核无 error 级问题 |
| 1 | **门控拦截**（规则包存在待核对条目，计算路径被拒）或基准未达标 |
| 2 | 输入不可用 / 参数错误（坐标不存在、文件缺失、格式非法、**校核命中 error 级问题**、**配额外部输入缺失**） |

- `_ensure_utf8_stdio()` 在 `main()` 首行调用（按 `stream.encoding` 探针决定是否 `reconfigure`，中文控制台 cp936 保持不动）——避免 CI cp1252 管道下 `UnicodeEncodeError`（08 环境坑）。
- `--json` 全局开关：所有子命令支持机器可读输出，便于批处理与测试对账。

## 七、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 官方原文核对耗时（M1） | 数值长期 pending，`calc` 不可用 | 骨架先行、门控可演示；M1 分批核对、逐条 `verified` 推进（每批都可交付） |
| 标准条款号引用不实 | 合规硬伤 | 未核对一律 `pending` + `"ref": "待核对"`；**禁止编造条号** |
| 因子库第二版摘录边界（版权/口径） | 发布合规 | 只摘数值+出处 URL（事实性数据），不转载正文；台账登记 |
| 打包后数据定位失真 | 交付物不可用 | `find_data_dir` 冻结分支 + `exe --selftest` 断言数据目录落在 dist 内（M5/M6） |
| 跨平台字节漂移 | 基准不可复现 | `.gitattributes eol=lf` + CR 守门 + `ZIP_STORED`（若产 zip 型冻结物） |

## 八、M0 决策速览（详细见 06）

1. 核心层零第三方依赖、零网络、零 LLM。
2. 规则包 JSON 化 + manifest 单点索引；代码零坐标字面量。
3. 门控单点 `effective_ruleset()`，全 pending 即拦截（M0 全部条目 pending，这是**刻意**的诚实初态）。
4. 单位换算因子（SI 定义型）单独 `units.json` 并标 `verified`——它是定义性关系而非政策数值，可即时核对。
5. 交付形态：CLI 先行（M0），GUI/打包后置（M5）。

## 九、M2 编排与数据流（详细见 04 §三、06 D2-*）

`cli.cmd_calc` 与未来 GUI **只调一个编排单点** `pipeline.compute_full`：

```
payload ──▶ effective_ruleset(coord, scope="calc")   ← 门控（pending → 退出码 1）
        ──▶ boundary.identify_boundary(...)          ← 纳入判定（缺输入 → 退出码 2）
        ──▶ calc.compute(...)                        ← 逐源：因子选择 → 单位链 → 表达式求值
        ──▶ factor_table / provenance                ← 因子来源表 + 溯源表（悬空引用 → 退出码 2）
        ──▶ render_report_text / report_head         ← 报告头（坐标+版本+时间）+ 各章
```

- **计算顺序硬性**（plan/04 §三）：门控 → 因子选择 → 单位换算 → 求值 → 汇总（行序按 `source_id` 排序）；
- **单一判定点**：纳入判定只此一处（`identify_boundary`），`calc` 不再各自维护一份"哪些源要算"；
- **可核证性**：溯源表行数 == 明细行数 + 因子表行数，且每行 `rule_entry_id` 必须可解析（NFR-06 / plan/04 §6.3）。
