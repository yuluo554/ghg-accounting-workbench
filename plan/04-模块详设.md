## 一、规则包 schema v1（`data/rules/ruleset-*.json`）

### 1.1 顶层结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema` | str | ✓ | 固定 `"ghg-ruleset/v1"` |
| `coordinate` | obj | ✓ | `{standard, year, industry}`，与文件名一致（加载器断言） |
| `standard` | obj | ✓ | 通则元数据（编号/名称/发布实施日期/代替关系/有效性/status/ref） |
| `boundary` | obj | ✓ | 排放源清单（§1.2） |
| `engine` | obj | ✓ | 公式与系数（§1.3） |
| `factors` | obj | ✓ | 行业默认因子与来源优先级（§1.4） |
| `quality` | obj | ✓ | 数据质量校核规则集（§四） |
| `quota` | obj | ✓ | 配额方法学配置（§五） |
| `report` | obj | ✓ | 报告模板变量（§六） |
| `provenance` | obj | ✓ | 生成器版本 + 出处台账 + 生成日期（**不含时间戳**，见 NFR-04） |

### 1.2 `boundary.sources[]`（排放源条目）

```json
{
  "id": "stationary_combustion",
  "name": "化石燃料燃烧排放",
  "category": "combustion",
  "applicable_industries": ["power", "steel", "cement", "aluminum"],
  "required": true,
  "clause": { "code": "GB/T 32150-2025", "article": "待核对", "note": "条款要点待核对" },
  "delta_vs_2015": "same",
  "status": "pending"
}
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `id` | 小写下划线 | **全局稳定标识**，跨版本同名源可比对；不得随年度改名 |
| `category` | `combustion` / `process` / `purchased_energy` / `carbon_product` / `other` | 用于公式分派与因子适用性检查 |
| `required` | bool | 该坐标下是否"应核算"；`false` = 选填 |
| `delta_vs_2015` | `same` / `added` / `removed` / `adjusted` | 双标尺差异提示的**数据源**（FR-01.3）；2025 版包内以此为相对基准 |
| `clause.article` | 条款号或 `"待核对"` | **禁止编造条号**；未核对写 `待核对` 且 `status=pending` |
| `status` | `verified` / `pending` | 门控对象 |

**双标尺差异算法（FR-01.3）**：以 2015 版包为基准，按 `id` 集合做差；`added` = 2025 有 2015 无；`removed` = 2015 有 2025 无；`adjusted` = 两版皆有但 `category`/`required` 变化。差异结果不得缓存进规则包（现算现出，避免第二份真相）。

### 1.3 `engine`（公式树 + 系数）

```json
{
  "formula": {
    "id": "emission_basic",
    "expr": { "op": "mul", "args": [
      { "var": "activity_data" },
      { "var": "emission_factor" },
      { "var": "oxidation_rate" }
    ]},
    "clause": { "code": "GB/T 32150-2025", "article": "待核对" },
    "status": "pending"
  },
  "coefficients": {
    "oxidation_rate": { "value": null, "unit": "1", "status": "pending",
                        "clause": { "code": "GB/T 32150-2025", "article": "待核对" } }
  }
}
```

**表达式文法（唯一允许的运算集）**

| `op` | 元数 | 语义 | 备注 |
|---|---|---|---|
| `mul` | n | 连乘 | Decimal 逐个相乘 |
| `add` | n | 连加 | 多燃料/多设施汇总 |
| `sub` | 2 | 差 | 净购入电力 = 购入 − 外送 |
| `div` | 2 | 商 | 分母为 0 时抛 `CalcError` |
| `const` | 0 | 常量 | **只能引用 `coefficients` 的 id**，禁内联数值 |
| `var` | 0 | 变量 | 只能引用 `inputs`（活动数据）/ `coefficients` |

- **零字面量在表达式层同样成立**：`{ "op": "const", "value": 3.14 }` 属非法，必须是 `{ "op": "const", "ref": "<coefficient_id>" }`。
- 求值器（M2 实现，M0 落 `engine.py` 骨架 + 校验器）：`evaluate(expr, scope) -> Decimal`；`validate(expr)` 在加载规则包时执行（检查 op 白名单、引用完整性、元数），非法即拒绝加载。

### 1.4 `factors`（来源优先级，FR-02.4 / FR-04）

```json
{
  "priority": ["measured", "official_db", "industry_default"],
  "industry_default_values": {
    "default_factor": { "value": null, "unit": "tCO2e_per_unit", "status": "pending",
                        "ref": { "source": "国家温室气体排放因子数据库（第二版）", "url": "待核对", "version": "第二版" } }
  }
}
```

| 优先级 | 键 | 进入条件 |
|---|---|---|
| 1 | `measured` | 企业提供实测因子（须带检测报告引用） |
| 2 | `official_db` | 命中官方因子库摘录（`data/factors/`，M1） |
| 3 | `industry_default` | 规则包内行业缺省值；**必须 `status=verified` 才可用** |

选择器输出 `factor_source` 三元组标签；若三层皆不可用 → 抛 `FactorUnavailable`（退出码 2），**不得静默取 0 或 1**。

## 二、边界识别引擎（M2 落地，M0 定接口）

```
identify_boundary(profile: FacilityProfile, coord: Coordinate) -> BoundaryReport
BoundaryReport = {
  coordinate, sources: [ {id, name, required, clause, included: bool, reason: str} ],
  missing_inputs: [str]
}
```

- `included` 仅当该源 `required=true` **且**企业档案提供了对应活动数据字段；
- `reason` = 纳入/排除的条款依据文本（来自 `clause`）；
- `missing_inputs` 非空 → CLI 打印并返回退出码 2（FR-01.4）。

**双标尺差异**：

```
diff_boundary(coord_2015: Coordinate, coord_2025: Coordinate) -> BoundaryDiff
BoundaryDiff = { added: [id], removed: [id], adjusted: [{id, field, from, to}] }
```

## 三、计算引擎（FR-02）

```
calculate(profile, coord, rules_index) -> CalcResult
CalcResult = {
  coordinate, lines: [EmissionLine], total: Decimal, unit: "tCO2e",
  warnings: [...], generated_meta: {tool_version, schema}
}
EmissionLine = {
  source_id, activity: {value: Decimal, unit: str}, factor: {value: Decimal, unit: str, source: str},
  coefficient_refs: [str], emission: Decimal, clause: {...}, provenance: {...},
  formula_trace: str          # 人类可读的代入过程，供报告"核算过程"章
}
```

计算顺序（硬性）：
1. `effective_ruleset(coord)`（门控，可能抛 `RulesetNotEffective` → 退出码 1）；
2. 逐源选择因子（§1.4 优先级）；
3. 单位换算到规则包声明的基本单位（`units.py`，换算因子取自 `units.json`）；
4. 按表达式树求值（全 Decimal）；
5. 汇总 `total`（位级确定性：行序按 `source_id` 排序，不依赖输入顺序）。

**量化呈现**：内部保留全精度，输出层 `quantize(PLACES, ROUND_HALF_UP)`；`PLACES` 由 `Decimal(1).scaleb(-n)` 表达（03 §五）。

## 四、数据质量校核层（FR-04）

### 4.1 规则 schema

```json
{ "id": "Q-UNIT-01", "type": "unit_consistency", "level": "error",
  "name": "活动数据单位与因子单位口径不一致",
  "clause": { "code": "GB/T 32150-2025", "article": "待核对" },
  "advice": "请统一到规则包声明的基本单位后重新录入",
  "status": "pending" }
```

`level` ∈ `error` / `warning` / `info`（FR-04.3）。

### 4.2 四类检查（type 分派）

| type | 检查内容 | 输入 | 判据来源 |
|---|---|---|---|
| `unit_consistency` | 活动数据单位 ↔ 因子单位 ↔ 规则包基本单位可换算且量纲一致 | profile + ruleset | `units.json` 量纲表 |
| `magnitude_outlier` | 单源排放量/活动数据是否越出规则包声明区间 | profile + ruleset | `quality.thresholds`（规则包内，禁硬编码） |
| `yoy_jump` | 同一源跨年度变化率超阈值 | 多年度档案 | `quality.thresholds.yoy` |
| `intensity_plausibility` | 比强度（如单位产量能耗）是否落在行业区间 | profile + 产量 | `quality.thresholds.intensity` |

- 阈值**全部在规则包内**（`quality.thresholds`），代码零阈值字面量（NFR-07）；
- 校核层**只读**：不得修改 `CalcResult` 任何字段（FR-04.4），由测试断言输入对象未被变更；
- 输出：`QualityReport = { issues: [{rule_id, level, source_id, message, clause, advice}], counts: {error, warning, info} }`。

### 4.3 与门控的关系

`pending` 的校核规则**不执行**（不得以未核对阈值报结论）；`check` 子命令在 `quality` 全 pending 时返回退出码 1 并说明原因，而非静默通过。

## 五、配额试算（FR-05，M3 落地）

```json
"quota": {
  "method": "benchmark",              // benchmark | historical_intensity | none
  "method_clause": { "code": "待核对", "article": "待核对" },
  "params": {                        // 数值一律 pending 待 M1 核对
    "benchmark_value":  { "value": null, "unit": "tCO2e_per_unit_output", "status": "pending" },
    "correction_factor": { "value": null, "unit": "1", "status": "pending" }
  },
  "status": "pending"
}
```

- `method != "none"` 时按方法学选择公式分支（**方法学切换即切换公式**，FR-05.1）；
- 输出 `QuotaResult = {allocated: Decimal, actual: Decimal, gap: Decimal, gap_ratio: Decimal, method, disclaimer_required: true}`；
- **免责声明强制**（R3）：`QuotaResult` 结构体不含可选声明——渲染层必须输出固定声明文本常量（该文本是**免责法律文本**，非政策数值，可入代码，见 06 豁免口径）。

## 六、报告导出（FR-06，M5 落地，M0 定模板）

### 6.1 章节骨架（Markdown）

```
# 企业温室气体排放核算报告（内部参考）

## 0 报告头（可复现三要素，FR-06.3）
   规则包坐标：通则 <code> / 年度 <year> / 行业 <industry>
   工具版本：<tool_version>
   生成时间：<timestamp>            ← 唯一允许的时间戳出现处（报告正文，不入冻结产物）
   免责声明：<固定文本>

## 1 核算边界
   1.1 企业概况（合成档案字段）
   1.2 应核算排放源清单（含纳入依据条款）
   1.3 双标尺差异提示（相对另一版通则）

## 2 逐排放源明细表
   | 源 id | 源名称 | 活动数据 | 单位 | 排放因子 | 因子来源 | 系数 | 排放量(tCO2e) | 依据条款 |
   合计行

## 3 因子来源表
   | 因子 id | 数值 | 单位 | 来源层级 | 来源出处 | 版本/日期 | status |

## 4 核算过程（逐源公式代入）
   源 <id>：<formula_trace>     依据 <clause>

## 5 数据质量校核结果
   问题清单（错误/警告/提示）+ 每条规则依据

## 6 配额试算（如启用）
   方法学、参数、结果、履约缺口预判、免责声明

## 7 依据清单
   | 编号 | 名称 | 发布/实施 | 状态 | 来源 URL |

## 8 数据溯源表（FR-06.2 核心）
   | 报告数字位置 | 值 | 活动数据来源 | 因子来源 | 规则条款 | 规则包条目 id |
```

### 6.2 机读产物

- `report.md`：人读；
- `lines.csv` / `provenance.csv`：机读（UTF-8 with BOM 便于 Excel；**无外链**，FR-06.4）；
- XLSX（M5）：最小 writer，`ZIP_STORED` + 固定 `create_system`（03 §五 字节确定性）。

### 6.3 溯源表完整性（可核证性断言）

- `provenance` 行数 == 明细表数据行数 + 因子来源表行数；
- 每行 `rule_entry_id` 必须能在该坐标包内解析到具体条目（测试断言）；
- 任一数字缺失溯源 → 导出失败（退出码 2），**不得导出"半溯源"报告**。
