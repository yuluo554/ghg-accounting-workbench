# v0.1.0 —— 企业温室气体排放核算与报告工作台

首个发布版本：**M0–M6 全部完成**。把「活动数据 × 排放因子 → 可核证报告」整条链做成
**可复现、可溯源、跨标准版本不混算**的本地工具。**全本地核算、零上传、零 LLM 依赖**。

## 这个工具解决什么问题

全国碳市场完成发电行业起步后，钢铁、水泥、铝冶炼已纳入扩围；GB/T 32150-2025 于 2026-07-01
实施（替代 2015 版），企业正处**新旧核算标准切换期**。痛点不是"不会做乘法"，而是：

- 新旧标准切换期，不敢断定"这版标准下要不要算这个源" → **双标尺排放源识别 + 差异提示**
- 活动数据 × 排放因子人人会算，"错在哪一项"说不清 → **逐项留痕**（活动数据 / 因子 / 规则条款三元组）
- 跨年度/跨行业规则包随手混用，算出来还不报错 → **三维坐标强约束**（跨坐标混算退出码 2）
- 申报前不知道自家数据"像不像话" → **四类数据质量校核**（分错误/警告/提示三级）
- 核查机构要"每个数字追到来源" → **一键可核证报告**（Markdown + CSV/XLSX + 数据溯源表）

## 亮点

**规则内核**：GB/T 32150 新旧双标尺 × 年度 × 行业 = **40 格三维版本化规则集**，
每格条目挂 `status` 门控（`pending` 不进计算路径），门控**按计算路径分作用域**（核算/配额/校核）。
**未核对不得生效**：核算路径 38/40 可通过，2026 年度发电碳氧化率因官方因子库 WAF 阻断而留白
——这是刻意的诚实留白，不是缺陷。

**可核证报告**：`ghg report` 一次落盘三产物（Markdown + 9 张 CSV + XLSX），章节覆盖 §0 报告头 … §8 溯源表。
**溯源行数 == 明细 + 因子**且每条 `rule_entry_id` 可解析（不得导出"半溯源"报告）；
机读产物**无外链**（断网可开、可归档）；XLSX 用自研最小 writer（零第三方依赖）且**同输入逐字节一致**。

**内置离线基准**（`ghg bench`，一条命令跑全三类）：规则自洽率 100%（480/480）、
因子与单位一致率 100%（116/116）、异常用例命中率 100%（12/12）、误报率 0%（8 个干净对照档案）。
单次全量 ≈ 0.04 秒。验收门槛随 manifest 下发（**门槛是数据不是代码**），
每套件配**可证伪探活测试**（注入缺陷 → 基准必须报未达标）。

**双形态交付**：CLI（纯 stdlib）+ PySide6 桌面（四页签：核算 / 校核 / 配额 / 基准）。
GUI **只消费引擎 API、零判定逻辑**（AST 导入门禁锁定）；**offscreen 测试常驻**（无显示器也能跑）；
PyInstaller onedir 双 exe，`exe --selftest` 断言**数据目录落在 dist 内**。

**发布面纪律**：零政策字面量门禁（扫描引擎 + GUI，token 集 13）；全历史提交元数据为 GitHub noreply；
脱敏审计四步可复跑（`tools/desensitize.py`）；随包数据走显式白名单（官方原文快照 11 MB 是核对留档，不进包）。

## 已知限制（如实列出）

- **官方因子库未摘录**：`data.ncsc.org.cn` 直连恒返回 HTTP 412（WAF），台账如实留空、
  不编造数值；缺省因子由四行业指南附录 A 官方缺省值承担。
- **核算路径 38/40**：2026 年度发电碳氧化率待因子库，该 2 个坐标核算路径被门控拦截。
- **配额平衡值属外部输入**：三行业行业平衡值仅平台可查，工具按外部输入显式索取（缺失即退出码 2，绝不静默取 0）。
- **首期四行业**：发电 / 钢铁 / 水泥 / 铝冶炼；其余行业留扩展。
- **CBAM 未做**：属 P2 扩展位，不阻塞首期。
